# 排版复审与中英文界面验收

日期：2026-11-01。基于前一轮前端优化继续复审。验收要求：同一表单行的选择框、输入框和操作按钮按控件底边对齐，不以文字基线对齐；中文默认，用户可主动切换英文，并持续使用所选语言。

## 排版修正

- 将资金、往来预算、会计、报表、附件与审计中的相关控件整理为 `control-row`，采用可换行的 Flex 布局和底边对齐。
- 统一控件高度为 38px，统一字段、控件和按钮间距。清除日期/时间输入框继承的额外底部边距。
- 长英文标签可换行，但对应控件底边继续对齐；手机端字段按纵向排列，按钮保持在所属操作分区。
- 对“来源追溯”行分别检查中文和英文的选择框、输入框、按钮：顶部及底部偏差均须不超过 1px。
- 逐页检查桌面表单行的控件底边，继续检查手机页面无整页横向溢出。

## 语言规则

1. 首次使用默认中文，不根据浏览器语言自动改成英文。
2. 登录页和登录后的页头均有切换按钮：中文界面显示 English，英文界面显示 中文。
3. 选择即时作用于全部页面，包括导航、标题、表单标签、占位提示、可访问名称、表格标题、状态、分页、图表图例、确认框、安全操作、校验与错误提示。
4. 偏好保存在当前浏览器的 `cfis.language` 中；页面跳转、刷新、退出和重新登录不重置。当前浏览器的其他标签页同步切换，不按企业重置。
5. 切换语言不提交表单、不修改财务数据，并保留正在填写的字段。
6. 企业名称、账户名称、分类名称、单据内容、业务说明、附件名称和原始审计详情保留原文。英文界面允许出现这些中文业务数据。
7. 日期时间按选择的界面语言显示；业务日期、企业时区、金额精度、币种和会计规则不因语言改变。
8. 常见服务端业务错误有对应英文译文；未识别的中文服务端错误在英文界面显示通用英文提示并保留追踪号。中文界面保留原始错误。
9. 本次为网页界面双语。Excel/PDF沿用现有服务端生成格式；不同设备或浏览器的语言偏好不自动同步。

## 实现与维护

- `frontend/src/i18n.ts`：语言状态、持久化、标签页同步、文案和消息翻译。
- `frontend/src/locales/en.json`：791 条英文词条，中文源文案作为键。
- `frontend/src/LanguageSwitch.vue`：统一切换入口。
- Element Plus 使用对应语言包；图表切换语言时重新绘制，不重新计算财务数据。
- 新增界面文字使用 `t()`，新增错误提示保持中文原始消息、在显示时翻译。不要对企业名称、说明等业务数据直接调用翻译。
- 已核对 851 处静态词条调用，无缺失英文映射。

## 验证

```powershell
npm.cmd run build --prefix frontend
./scripts/test-browser.ps1
```

最终生产构建通过（6.55 秒）。浏览器回归 **7/7 通过，59.3s**；前端与 API 就绪检查均返回 HTTP 200。真实 API 浏览器回归覆盖原有资金、往来预算、会计、邀请、分摊及附件流程，另含逐页响应式和双语验收。

双语专项覆盖：中文默认、全部 9 个页面英文、桌面及手机无界面中文漏译、来源追溯行中英文精确对齐、表单行对齐、语言切换保留输入、刷新、退出再登录、切回中文、其他标签页同步，以及中文业务名称不被翻译。英文安全操作逐项检查邀请、接受邀请、找回密码、修改密码。服务端日期校验错误也检查英文显示。

成员权限选择框与两个操作按钮也有精确位置断言。截图复核补齐了 CSS 生成的窄屏滑动提示翻译，并修正英文空状态文本换行后的行距。空状态按表格可见宽度定位，检查文字边界完整位于表格内，避免被横向滚动层挤出。浏览器测试固定 3 个工作进程，业务异步操作等待真实响应完成，异步页面加载后才测量位置；失败自动保留截图和追踪记录。
